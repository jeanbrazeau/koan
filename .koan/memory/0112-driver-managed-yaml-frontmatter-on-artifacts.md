The koan artifact persistence layer (`koan/artifacts.py`, `koan/web/mcp_endpoint.py`) stores phase-produced artifacts as markdown files under `~/.koan/runs/<id>/*.md`, each carrying a driver-managed YAML frontmatter preamble that is LLM-invisible: `koan_artifact_view` strips it via `split_frontmatter()` before returning the body, and the LLM never sees or writes frontmatter. Leon added the frontmatter layer on 2026-04-25 with three fields (`status`, `created`, `last_modified`). On 2026-06-02 Leon removed the `status` field entirely: `STATUS_VALUES = ("Draft", "Approved", "In-Progress", "Final")`, `read_artifact_status()`, and the `status` parameter of `write_artifact_atomic(target, body)` and `koan_artifact_write(filename, content)` are gone; frontmatter now carries only `created` and `last_modified`. Rationale: the status taxonomy was never read by any code path -- `api_artifacts_list` and `build_artifact_diff` key on path/size/mtime only, the projection fold never tracked it, and the orchestrator's conversation context already holds whatever lifecycle state matters. Leon chose status-only removal over making artifacts fully frontmatter-free: `created`/`last_modified` and the `split_frontmatter` / `dump_frontmatter` / `compose_artifact` helpers were kept, because "state" meant the orchestrator-set lifecycle marker, not the passive timestamps. Prompt prose that had used `status="Final"` / `status="In-Progress"` to signal 'frozen at exit' or 'reviewer may rewrite in place' was reworded to plain prose with no status field.

The same change added a second mutation tool, `koan_artifact_edit(filename, old_string, new_string)`, as the surgical counterpart to the full-rewrite `koan_artifact_write`. It replaces exactly one occurrence of `old_string` in the frontmatter-stripped body (so `old_string` matches what `koan_artifact_view` showed the caller) and raises `ToolError` on file-not-found, zero matches, more-than-one match, or a degenerate edit (empty `old_string`, or `old_string == new_string`); there is no `replace_all`. Parameter names `old_string` / `new_string` were chosen for parity with the orchestrator's built-in Claude `Edit` tool (alternatives `old_text`/`new_text` and `find`/`replace` rejected -- the latter implies multi-match, contradicting the single-match contract). Like `koan_artifact_write`, it re-attaches managed frontmatter through `write_artifact_atomic` (preserving `created`, refreshing `last_modified`), emits `artifact_diff`, and is allowed for the orchestrator role in every phase; the four review phases (`plan_review`, `exec_review`, `tech_plan_review`, `milestone_review`) were updated to prefer it for targeted in-place fixes over full-content rewrites. Both tools live in `koan/web/mcp_endpoint.py` and share `write_artifact_atomic`; PyYAML usage is `yaml.safe_dump(meta, default_flow_style=False, sort_keys=False)` / `yaml.safe_load`, malformed frontmatter falls back to `(None, original_text)` with a logged warning, and the older `koan_artifact_propose` tool remains retired. The artifact lifetime taxonomy (frozen / additive-forward / disposable) in `docs/artifacts.md` is a separate concept and was not affected by the status-field removal.
